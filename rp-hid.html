Raspberry Pi Keyboard+Mouse Demonstrator

Jul 2026 - Aug 2026
Languages: C, C++

This project's goal was to experiment with both hardware and software, using real-world applications such as Bluetooth. The product is a human interface device (HID) with 8 buttons and a joystick, capable of sending keyboard and mouse inputs to Windows 11 computers. A host-app runs on the computer and allows two-way communication with the device.

TLDR: The video summarizes this project.

Hardware

- Raspberry Pi Pico W (with wireless capaiblities)
- 8 push buttons
- 2-axis joystick

Firmware

The device has two modes, wired and bluetooth. The firmware, written in C, reads inputs from the buttons and joystick and sends them to the computer.

In wired mode, the device uses TinyUSB, a library that allows wired communication from the Pico W to the computer. The computer recognizes the device as a keyboard and the firmware sends keyboard inputs to Windows' keyboard drivers.

In Bluetooth mode, the firmware uses the BTStack library, enabling Bluetooth communication and meaning the device does not need to be plugged into the computer, only to a power source. The Pico W uses on-board flash memory to remember previous connections and reconnect automatically after losing power.

Software

A custom made host app can be used on the computer to interface with the device. While the device communicates with the computer, the host app enables the computer to communicate with the device. This enables functions like updating the device's firmware without putting the Pico W into boot mode (i.e. while the device is functioning). This host app is entirely optional as the device can still send keyboard and mouse inputs without it.

Capabilities

The 8 buttons send keyboard inputs corresponding to F13-F20, rarely used keys. Meanwhile, the joystick can simultaneously move the mouse. The 8 buttons can be remapped to other keys by changing the firmware. This method changes what keys the device itself sends. Other methods includ using third party software, such as AutoHotkey (AHK). Using AHK scripts, the F13-F20 keys can be reassigned to other keys or even actions. The host app also can remap keys. Within the host app, buttons can be assigned to keys or actions including volume up/down, CTRL+C, or open an application. Notably, the host app reads the raw button states (which buttons are pressed), bypassing the Windows keyboard driver. This means instead of reading F13-F20, the host app reads button 1, button 2, etc. For applications such as a game controller, reading the raw button states instead of going through the keyboard driver woud be beneficial.

In Bluetooth mode, the device retains full functionality. The only functional difference is that it communicates wirelessly rather than through a USB port.

Limitations

It was initially attempted to use BTStack's classic Bluetooth implementation. However, this implementation was laden with difficulties. The device would be recognizable to Windows, however when attempting to connect, the device would always disconnect after 3-10 seconds. When running BTStack's own Bluetooth demo, it would encounter the same issue. Thorough troubleshooting revealed the issue was with Windows 11's Bluetooth compatibility policy. Indeed, when connecting to an Android device, no issues were encountered. Windows 11 was terminating the connection and there was seemingly no solution, as even BTStack's own example failed to work.

The work-around involved using BTStack's Bluetooth Low Energy (BLE) implementation. This resolved the disconnection issue, however, the device suffered from very poor latency. This made it unusable in time-critical applications such as a game controller. The Bluetooth connection was also poor, as the device would disconnect intermittently. A future iteration of this device would use a different Bluetooth implementation, in an attempt to pass Windows security checks while maintaining usable latency and connection strength.
